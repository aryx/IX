The tiny system, running in this page

IX · The machine · What to try · How it is in a page · The tiny programs

Each program of IX comes in two sizes. The tiny ones, t-IX, are the free variants: one file each, what is left of a program when compatibility is dropped and only its idea is kept. Among them are a machine of our own design, a kernel for it written in ML, a window system and a game. Below, they run: the machine is the OCaml program, compiled to JavaScript; everything on it is the tiny system's own code, compiled by its own compilers.

The machine



The machine needs JavaScript.




Boot another kernel:
tiny-kernel (in ML; the screen, the windows) ·
tiny-os t6 (in C; a free kernel) ·
tiny-os v6 (in C; xv6's kind of kernel, with pages and a disk).
The last two have no screen: their console is the text.




What to try




What you type goes to the console, the text under the screen, as in a
terminal: the line shows as you type it, and Enter gives it to the
shell. With the mouse in the screen, the keys go to the screen's
programs instead, one by one: to the window under the mouse, once
there are windows, or to a game.



    

  • ls — the programs and the files; echo hi | cat > f, cat f, wc < f, mkdir d: the shell has pipes and redirections.
    • 

  • tiny-windows — the window system. In the screen, the right button gives a menu: New, then sweep a rectangle with the left button held, and a shell runs in it. Type ls there.
    • 

  • tetris, typed in a window (the mouse in it) — the arrows move and turn the piece, the space drops it.
    • 

  • paint — a program that draws, on the screen or in a window; square, a game of a page.
    • 

  • tiny-windows typed in a window — the window system in one of its own windows: a window looks to a program like the machine.
    • 





A note on speed. The machine is paced, as a real one is: it runs a
fixed number of instructions each second, so that a game plays the
same on a fast computer and on a slow one. Compiled to JavaScript, it
is not yet fast enough to keep that pace in most browsers. The line
under the console says how close yours gets: at 60%, everything works,
and tetris falls at 60% of its speed. Making the machine faster is the
next thing to do. (A phone has no keys to type with.)




How it is in a page




tiny-machine is 16 registers, one instruction format, two modes, one
trap, a timer that counts instructions, pages, a console, a disk, a
screen of 640 by 480 bytes and a mouse. It is three files of OCaml:



    

  • TinyLibCPU.ml — the CPU: its instructions, its assembler, its interpreter;
    • 

  • TinyLibMachine.ml — what a kernel needs around it: the registers of control, the traps, the pages, the devices;
    • 

  • TinyMachineWeb.ml — this page's part: the screen on a canvas, the keys, the mouse, a slice of instructions at each frame. In a terminal the same machine is TinyMachine.ml.
    • 




js_of_ocaml compiles
them to about 90 KB of JavaScript. The page fetches that and the
kernel's image, 1.2 MB for tiny-kernel with its programs: no server
runs anything. On the machine,
TinyKernel.ml,
TinyWindows.ml and
TinyTetris.ml
are ML compiled by tiny-ml, and tiny-os is C compiled by
tiny-c, both for this CPU.




From a checkout, ./tiny-machine -window tiny-kernel runs it
in a window of your own machine, and
./tiny-machine -web dir tiny-kernel makes this page's
files.
